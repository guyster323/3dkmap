## 1. Target read — 기준이 실제로 요구하는 것

### 1.1 UI chrome: 얇은 역사 창틀과 읽을 수 있는 계층

제품 목업은 지도 위에 좌측 브랜드/나무 메뉴, 상단 권·장 타임라인, 우상단 이동·인물 패널, 지도에 붙은 사건 배너, 하단 사건 장면과 연표를 놓는다. 창은 각지고 내부는 거의 검정에 가까운 짙은 남색이며, 가는 금색 선과 작은 모서리 장식이 윤곽을 만든다. 지도와 같은 장면에 속한 창틀이다. 넓은 파란 면과 굵은 버튼으로 구분하는 웹 대시보드가 아니다.

스타일 가이드의 UI·배너·트리 예시가 요구하는 구체 요소:

- 브랜드는 작은 상태 문자열과 구분되는 금색 워드마크다. 한국어 제목은 금색, 내용은 따뜻한 상아색, 보조 정보는 낮은 대비로 계층을 만든다.
- 트리는 책/지역/사건/인물 네 그룹이며, 가지선·들여쓰기·선택 행으로 관계를 보여 준다. 목업의 책 트리는 **한 세로 기둥 안에서** 펼쳐진다.
- 상단 왼쪽은 `전략 삼국지 N권`과 **권 제목**, 오른쪽은 해당 권의 장 이름과 연결선, 활성 장이다. 날짜만 강조하거나 숫자 네 개만 나열하는 방식이 아니다.
- 배너는 그림, 연도·월, 제목, 최대 두 줄 설명, 기본/호버/선택 상태를 공유한다. 호버의 강조는 테두리에 집중한다.
- 장면은 배너에서 이어지는 확대 창이다. 배경·작은 배우·초상·이름·대사·출처·진행 상태가 함께 읽힌다.

목업은 여러 시대 사건과 여러 패널을 한 장에 보여 주는 제품 구도 예시다. 모든 패널을 초기 화면에 동시에 켜라는 요구로 해석하지 않는다. 목업에 적힌 권 번호·사건 날짜·국경·게임형 수치도 역사 데이터의 출처가 아니다. `Prompt.md` §2, §5–6, §11–12의 지도 우선 원칙과 기존 역사 자료가 우선한다.

### 1.2 Map: 지리 위에 세운 고밀도 ¾ 픽셀 지도책

목업의 중심에는 산맥의 능선, 수관이 구별되는 숲, 황토색 길과 들판, 성벽·궁궐을 갖춘 도시, 부대, 돛단배, 짙은 바다와 섬이 있다. 작은 사물들이 반복되지만 지역별 형태와 군집이 다르다. 도시 주변은 생활·군사 거점의 밀도, 산악은 높은 실루엣, 바다는 상대적으로 조용한 면과 선박·항로로 읽힌다.

- 카메라는 북쪽이 위인 지리 위에 지붕과 두 면의 벽이 드러나는 쿼터뷰다. 지도 전체를 마름모 타일판으로 바꾸지 않는다.
- 바다는 깊은 청색, 해안은 밝은 경계, 강은 지형을 따라 이어지는 통로다. 동아시아와 한반도 및 주변 수역을 알아볼 수 있어야 한다.
- 수목/산/성곽/선박의 광원과 픽셀 덩어리 크기가 일치한다. 스타일 가이드의 빛은 좌상단이다.
- 세력은 큰 천 깃발과 작은 거점 깃발, 옷/갑옷의 포인트로 읽힌다. 넓은 영토색 면이 지형을 대체하지 않는다.
- 수도는 궁전·중정·성벽으로 된 복합체, 주요 도시는 완결된 성곽, 군현은 소규모 성벽, 마을은 지붕 몇 채다. ‘같은 도시를 작게/크게’만으로 끝내지 않는다.

`Prompt.md` §7은 기존 전략 지형 렌더러의 개선, 결정적 타일 렌더링, 지리 인식, `imageSmoothingEnabled = false`, 가능한 정수 픽셀 배율, DOM 한국어 라벨을 함께 요구한다. ‘픽셀이므로 해안을 단순하게 그려도 된다’는 예외는 없다.

### 1.3 Assets: 동일한 문법, 서로 다른 인물과 사건

스타일 가이드의 초상은 얼굴·수염·머리장식·연령·체형이 구분되는 상반신이다. 녹색/적색/청색은 인물의 옷과 깃발에 쓰이며 얼굴을 다른 세력 색으로 물들이지 않는다. 지도 병사와 장면 배우도 이 정체성을 이어간다.

배너의 황건 봉기·관문 전투·적벽 화공은 그림만으로 소재가 구분된다. 확대 장면에는 행위의 무대와 배치가 있다. 같은 복숭아밭이나 불타는 배를 임의의 사건에 붙이는 것은 이 요구를 충족하지 않는다.

`Prompt.md` §3, §8–14가 정한 제작 방식은 **Grok Imagine의 원본 master → Pillow의 규격화 → atlas/manifest → runtime**이다. 주요 인물, 건축, 함선, 부대, 사건 장면의 원본 시각 설계를 먼저 확정한다. 최종 크기·크롭·팔레트·투명도·아틀라스 좌표는 코드가 결정한다. KOEI 디코딩/타일/스프라이트, Yokoyama 원화·패널·대사 복제 및 픽셀 트레이싱은 금지한다.

### 2.2 지도, 지리, 도시, 병력

- 원본 `public/assets/pixel-times/terrain/world-map.png`는 1024×704. 실제 화면은 넓은 올리브색 평야, 동일 삼각형이 줄지은 서쪽 산, 남서부의 어두운 숲 덩어리, 파란 수로 띠, 해면 전체의 밝은 점무늬다. 수관·능선·경작지·마을을 따라 읽는 밀도가 부족하다.
- `StrategicMapCanvas.tsx`는 이 PNG를 canvas에 그리고 SVG 영토 다각형과 도시 간 직선을 얹는다. 이것은 런타임에서 세밀한 지형 타일을 재조합하는 렌더러가 아니다. 기존 결정적 이미지 합성 기반을 살려 개선할 수 있다.
- `scripts/build_world_map.py`의 `land_kind()`는 타원과 수식으로 육지를 만들며 코드 자체도 ‘Not a survey’라고 쓴다. 결과의 한반도 남부/중국 동해안은 사각 절단과 어색한 평행 경계로 읽힌다. 황하의 정체성이 없고 장강은 바다까지 자연스럽게 이어지는 강망으로 보이지 않는다. 해면의 거품 처리도 너무 넓어 소금 뿌린 반복무늬처럼 보인다.
- 좌표는 1000×700, 배경은 1024×704인데 같은 프레임으로 늘어난다. 중심 `cover`는 viewport를 채우는 대신 지리를 자른다. 375×812에서 canvas는 x=-392.5, 폭 1160px. 768×1024에서는 x=-347.5, 폭 1463px다. 가로 overflow는 없지만 보이지 않는 지리가 생긴다.
- 375에서 지역 트리 → 국내성을 눌러도 선택만 바뀐다. 국내성 버튼 x=534.375, 폭 44px로 화면 밖에 남았다. `focusPlace`는 카메라를 이동시키지 않는다. 현재 pan/zoom 인터랙션도 이 컴포넌트에는 없다. 데스크톱도 위쪽 국내성 일대가 헤더에 가려진다.
- 도시 원본은 수도 96×80, 주요 도시 64×56, 군현 40×32지만 실제 수도와 주요 도시는 모두 가로 44px다. 낙양 실측 44×36.65625, 탁군 44×38.5. 44px flex 부모와 이미지 크기 제약이 등급 차이를 지운다. 군현은 단순한 빨간 삼각 지붕 두 채여서 섬세한 수도보다 오히려 더 크고 거칠게 보인다.
- `CITY_SRC[node.tier]`만 사용하며 sidecar의 `cityTier`와 `landmark`는 도시 선택에 반영하지 않는다. 마을/관문 PNG가 존재해도 이 렌더링 경로에서는 쓰이지 않는다. 원본 수도도 길쭉한 성곽 하나를 여러 곳에 반복한다.
- 군대/배는 일부 도시 sidecar에 정적으로 붙는다. `landmark-army.png`는 짙은 삼각형·깃발·타원 그림자, `landmark-ship.png`는 삼각 선체·빨간 막대, 항구는 직사각형이다. 병사 군집·돛·갑판·부두로 읽히지 않는다. 지도 전용 인물 atlas도 있으나 이 전역도 경로에서는 사용하지 않는다.
- 영토는 전달된 전체 배열에 `fillOpacity=0.18`, 윤곽 `0.7`을 적용한다. 컴포넌트에는 에피소드 시각별 필터가 없다. 연도별 정확성은 별도 역사 검증 대상이며, 지금 이 레이어를 더 진하게 해서는 안 된다.

### 2.3 초상과 배너: 파일 수와 시각 다양성이 다르다

PNG를 RGBA로 디코딩한 뒤 픽셀 바이트 SHA-256으로 비교했다. 파일명/압축 차이 검사가 아니다.

| 자산 계열 | 현재 수량/규격 | 확인된 상태 |
|---|---|---|
| masters | 67개, 832×1248 | 실제 서로 다른 픽셀 66개. 조인/장합 master 동일. |
| portraits | 67개, 64×80 | 서로 다른 픽셀 65개. `cao-ren` = `zhang-he`, `liu-zhang` = `meng-huo`. |
| map-sprites | 67개, 32×64 | 조인/장합 동일. |
| scene-actors | 134개, 48×64 | 조인/장합의 양 프레임 동일. 유장/맹획의 f1도 동일. |
| event-banners | 72개, 320×180 | 픽셀 해시는 모두 다르지만 대부분 세 배경의 크롭/색보정 변형. |
| scene-backgrounds | 3개, 480×270 | 복숭아밭·산문·불타는 배. 소재는 구분되나 전체 사건을 감당할 수 없다. |
| terrain | 10개 PNG | 수도/주요 도시와 나머지 단순 도형 자산의 수준·카메라가 불일치. |

**조조 ≠ 영제는 반드시 지킬 회귀 조건이지만, 이번 파일에서는 두 초상이 실제로 다르다.** 현재도 동일하다고 보고하지 않는다. 대신 같은 결함군의 확정 증거가 조인/장합과 유장/맹획에 남아 있다. 초상 atlas에서는 얼굴뿐 아니라 청록/자홍 배경 잔류, 녹색 피부, 같은 문관 얼굴·포즈·모자의 반복이 보인다. 기준의 성인 무장 흉상에 비해 일부는 큰 머리·단순 얼굴의 만화형으로 기운다.

원인도 코드에서 확인된다. `scripts/fill_remaining_cast.py`는 세력별 template master를 색/명도/채널 교환하고 모서리에 작은 표식을 넣는다. 고구려를 사마의, 기타를 제갈량 계열로 매핑한다. 이런 변형은 고유 인물을 만들지 않는다. 채널 교환으로 마젠타 배경이 청록색이 되면 마젠타 전용 키 제거를 통과하지 못할 수 있고, atlas에서 그 잔류가 실제로 보인다.

배너는 `scripts/build_event_banners.py`에서 event ID 해시로 세 배경 중 하나를 고른 뒤 크롭/색보정/문자 띠를 추가한다. 연락시트의 `ev-208-chibi.png`는 복숭아밭, `ev-184-saroguk.png`는 불타는 배다. 다만 적벽 대표 에피소드의 hand mapping은 별도의 `v26-e01.png`를 사용하므로 **모든 적벽 화면이 복숭아밭이라고 일반화하지 않는다.** 기본 `/world`의 황건 배너 `v01-e01.png`는 봉기 군중 대신 조용한 산문이다.

`event-scenes.ts`도 낙양 화재와 오소 군량고 화재에 `chibi.png`, 융중대에 `taoyuan.png`를 연결한다. 지도 배너가 이벤트의 장소·행동을 설명하지 못하는 문제다. 장면 배우는 `col/row` 값이 있어도 현재 overlay에서 아래 중앙 flex 행으로 나열된다. 생성 후처리의 기본 f1은 전체 배우를 한 픽셀 위로 이동시키는 방식이다. 개별 생성 프레임이 디스크에 있더라도 현재 atlas가 모두 그것을 사용한다고 가정하면 안 된다.

## 4. UI/UX direction — 지도 위 HUD를 어떻게 마무리할 것인가

### 4.1 먼저 고칠 구조와 화면 예산

수정 위치는 `src/app/world/page.tsx`, `src/components/pixel-times/`, 필요 범위의 `src/app/globals.css`다. 이미 있는 무대를 유지하고 아래 예산을 적용한다. 수치는 PNG에서 추출한 사실이 아니라 **다음 구현의 검수 가능한 시작값**이다.

| 화면 | 상단 | 나무 메뉴 | 기본 사건 표시 | 지도 가시성 |
|---|---|---|---|---|
| 1440/1920 | 80–96px 이내. 브랜드/권 제목, 장 레일, 이동을 가로로 배분 | 208–240px 한 기둥. 필요한 그룹 하나만 확장 | 대표 배너 1개, 나머지 marker. 선택 시 보조 카드 | 장면 닫힘 기준, HUD/카드 제외 실제 지도 노출 약 70% 이상. 중국–한반도/황해 관계 확인 |
| 768 | 88–104px 이내. 불필요한 인물 plate 제외 | 기본 4탭 176–192px 가로형. 열 때 224–240px 단일 도크 | 1개 compact, chronicle 접힘 | 최소 65% 지도 노출. 데스크톱 184px 메뉴+옆 패널을 그대로 적용하지 않음 |
| 375 | 96–112px 안에서 현재 권·장 제목을 읽을 수 있는 두 행 | 기본 높이 44px 4탭. 열면 약 224px 폭, 최대 40dvh | marker 또는 최대 약 152px compact. chronicle는 44px 진입점 | 기본 약 65% 지도 노출. 좁은 viewport에서 선택 위치를 볼 수 있는 카메라 제공 |

모든 판정은 지도만 열린 기본 상태, 트리 하나가 열린 상태, 사건이 선택된 상태를 분리한다. 장면 열림은 집중 상태이므로 70% 노출을 강제하지 않는다. 대신 데스크톱에서는 장면 주위에 지도 맥락이 남고, 모바일은 닫기 한 번으로 같은 위치에 돌아와야 한다.

남색 면을 줄이려고 제목을 9–11px로 압축하지 않는다. 불필요한 단어·중복 설정·중첩 창을 제거한다. `.eik-win`/`.eik-body` 같은 일반 규칙이 Tailwind 폭/폰트 유틸리티를 덮는 현재 상태부터 확인한다. 배너 요약은 코드에 `text-[11px]`가 있어도 실측 14px/23.8px였다. 의도와 computed style가 일치해야 숫자로 설계할 수 있다.

### 4.2 권·장 타임라인

데스크톱 왼쪽 180–220px 안에 `전략 삼국지 N권`과 **volume.title**을 두 줄로 놓고, 가운데를 해당 권 장 레일에 배분한다. 장 노드는 6–8px의 점/마름모, 연결선 1px, 시각적으로 낮은 대비의 비활성 상태다. 각 노드 아래 `N장`과 짧은 장 제목을 표시한다. 활성 장만 주홍 또는 밝은 금색으로 표시하고 제목 대비를 높인다. 44px 이상의 클릭 영역은 유지한다.

모바일은 첫 행에 브랜드/권 정보, 다음·다음 권의 44px 버튼을 배분하고, 둘째 행에 현재 장 제목과 필요한 장 레일을 둔다. 공간이 모자라면 비활성 장의 제목은 줄이되 **현재 장 제목은 따로 읽히게** 한다. 많은 장은 레일 내부 가로 스크롤을 허용하고 페이지 전체 overflow를 만들지 않는다. 긴 연호·서기 중복은 보조 팝오버/상세로 보낸다.

`시계 정지`는 제거한다. `▶ 다음 장`, `▶▶▶ 다음 권`은 `Prompt.md`의 이산적 이동 의미로만 쓴다. 아이콘만 보이는 폭에서는 accessible name/tooltip을 유지한다. play/pause 토글, 배속, 자동 진행, 시간 scrubber를 추가하지 않는다. scene actor idle과 물/깃발 FX는 장을 바꾸지 않는다.

### 4.3 네 나무 메뉴

`TreeDock.tsx`의 메뉴 헤더+옆 flyout을 **한 외곽 창 내부 아코디언**으로 바꾼다. 시각 순서는 그룹명 → 권/지역/세력 → 장/장소/인물이며, 선택 행은 얇은 금색 표식과 어두운 강조 바탕으로 보인다. 부모 권과 현재 장을 모두 큰 금색 면으로 칠하지 않는다.

- 그룹 하나만 확장한다. 1440 이상에서는 책을 기본으로 펼쳐도 화면 예산을 지키면 허용하지만, 375/768은 기본 접힘을 유지한다.
- 행은 최소 44px. 펼침 화살표와 선택을 분리해야 한다면 두 타깃을 겹치지 않게 하고, leaf에는 무조건 44px 공백을 남기지 않는다. 12–16px 가지선/들여쓰기로 관계를 만든다.
- 지역을 고르면 지도 카메라가 그 지역의 안전한 범위를 보여 준다. 선택만 바꾸고 화면 밖 노드를 남겨 두지 않는다. 지도 위치 선택과 상세 페이지 이동은 구분한다.
- 사건은 연대/원정별 그룹으로, 인물은 세력별 그룹으로 유지한다. 인물 leaf를 누르면 같은 HUD의 선택 인물 정보가 열려야 한다. 현재처럼 눌러도 아무 결과가 없는 버튼을 완성으로 처리하지 않는다.
- 키보드의 펼침/닫힘/위아래 이동/선택 후 포커스가 일관되어야 한다. 열리고 닫히는 패널이 포커스를 화면 밖에 가두지 않게 한다.

### 4.4 배너와 충돌 예약

`MapBannerLayer.tsx`의 `ZONE={18..58,16..52}`, 가짜 % 폭/높이, 낙양 전용 offset을 지우는 방향으로 설계한다. ‘지도 전체 좌표’와 ‘현재 보이는 viewport’는 다르다. 실제 DOMRect를 기준으로 다음을 한 번에 배치한다.

1. 상단 HUD, 열린 트리, chronicle/선택 카드의 사각형을 먼저 예약한다.
2. 현재 선택 도시의 이미지 외곽과 44px 타깃, 우선 도시 라벨을 예약한다.
3. 대표 사건 배너는 앵커 주변 NE/SE/NW/SW 후보를 평가하고 8–12px 간격을 둔다. 이동한 카드에서 원래 장소까지 가는 가는 픽셀 leader와 끝점을 표시한다.
4. 자리가 없으면 위치를 무한히 밀지 말고 compact → 44px marker로 단계적으로 축약한다. 한 사건이 차지하는 형태는 하나만 유지한다.
5. 팬/줌/리사이즈/트리 열림 때 다시 계산한다. HUD·배너·라벨이 서로 다른 충돌 알고리즘으로 같은 영역을 예약하지 않게 한다.

대표 배너는 데스크톱 224–256px 폭, 그림 80–96×45–54px, 날짜 11–12px, 제목 13–14px, 설명 두 줄을 시작값으로 한다. 기본 높이는 약 84–112px 안에서 실제 폰트로 검수한다. 모바일 marker 탭 → compact/상세 배너 → 장면으로 연결하고 전체 화면 폭의 설명 카드를 상시 띄우지 않는다. 밝기 필터만으로 hover를 처리하지 말고 금색 테두리/선택 표시를 공유 컴포넌트에서 통일한다.

### 4.5 Chronicle·선택 정보·장면

chronicle는 `날짜 | 사건 제목`의 44px 행으로 만든다. 현재 선택 사건을 강조하고 같은 시각의 다른 사건을 이어서 보여 준다. 전체 설명과 다수 출처 badge는 행을 선택했을 때 나타나는 상세 영역에 둔다. 모바일 기본은 `그 시각 사건 N` 진입점, 열면 최대 35–40dvh의 목록으로 충분하다. 선택 장소 요약과 chronicle 상세는 같은 보조 자리에서 교대하며 두 큰 패널을 동시에 추가하지 않는다.

지도 현재 상태에 모두 `대기`를 붙이는 표현은 제거하거나 실제 의미가 있을 때만 쓴다. 성인/가족 텍스트 설정은 2차 설정 접근점으로 옮기되 기존 기능은 유지한다. 출처와 불확실성은 삭제하지 않고 상세에서 읽기 좋게 유지한다. 목업의 군량/인구/능력 별점을 장식용 허구 수치로 새로 만들지 않는다.

장면은 데스크톱 오른쪽/아래의 별도 창으로 시작한다. 480×270 배경의 1× 또는 2×가 들어갈 수 있는지 먼저 계산하고, 1440 화면에서 창 외곽은 대략 720–1000px 범위, 높이 80dvh 이하를 목표로 한다. 배경 2×가 공간에 안 맞으면 실제 viewport에 그리는 축소 LOD를 준비하거나 1×와 작은 여백을 쓴다. `w-full`로 480px 그림을 임의의 1404px까지 늘리지 않는다. 모바일에서는 화면을 사용하는 dialog가 가능하지만 닫기·대사·출처는 화면 안에 있어야 한다.

`EventSceneOverlay.tsx`는 actor의 `col/row/dir`를 배경의 공통 좌표로 투영하고 발 위치로 깊이 정렬한다. 배우를 하단 한 줄로 정렬하지 않는다. 대사는 작은 초상/이름/본문 한 창, 진행은 `현재/전체 대사`와 수동 다음 버튼으로 표현한다. 닫으면 선택 장·카메라·포커스가 돌아온다. 전역 시계와는 독립적이다.

## 5. Map direction — 지리 골격과 그림 밀도를 함께 고친다

### 5.1 먼저 만들 한 장의 기준 지역

전국의 타일을 한꺼번에 교체하기 전에, 낙양–장안–황하 주변과 산둥–황해–한반도가 함께 읽히는 구간을 축소 제작한다. 최소한 수도, 군현, 산맥, 숲, 강 건넘, 해안, 항구, 배, 작은 군대가 한 화면에 있어야 한다. 제품 목업을 옆에 두었을 때 이 구간만이라도 같은 미술 문법으로 읽힌 뒤 전국으로 확장한다.

작업 순서는 **지리 좌표 → 해안/강 mask → 지형 군집 → 도로/거점 footprint → 도시/부대/배 → DOM 라벨 → HUD 충돌**이다. 지금처럼 단순 배경을 다 만든 뒤 노드마다 화려한 도시 이미지를 얹으면 바탕과 사물의 해상도가 계속 분리된다.

### 5.2 지형 밀도: 잡음의 수가 아니라 읽히는 사물의 수

`world-map.png`의 광역색을 대체할 기본 규칙:

- **평야:** 같은 미세 점무늬를 전면 반복하지 않는다. 흙길, 작은 경작지, 풀 무더기, 낮은 관목, 소수의 민가가 물길과 거점 주변에 모이게 한다. 나머지는 조용한 중간톤으로 남긴다.
- **숲:** 3–5종의 수관 master와 작은 수풀을 크기/밀도별 군집으로 배치한다. 같은 타원을 모든 타일에 찍지 않는다. 숲 가장자리에는 큰 나무→작은 나무→관목→평야의 이행이 보여야 한다.
- **산:** 4–6종의 봉우리/능선/암벽 master를 실제 산지 흐름에 맞춰 연속 배치한다. 봉우리 높이, 좌상단 밝은 면, 우하단 그림자, 산기슭의 숲을 연결한다. 같은 삼각형의 수평 행과 평행 사선 패턴이 보이면 실패다.
- **강:** 기본 수면과 얕은 둑, 강굽이, 합류부, 강폭 변화, 하구를 그린다. 장강을 폭이 일정한 파란 테이프로 끝내지 않는다. 강 옆 SVG 직선이 다른 강처럼 보이지 않게 한다.
- **바다:** 해면 대부분은 짙은 청색 중간톤, 해안과 선박 주변만 밝은 포말을 쓴다. 현재처럼 전 수역이 흰 점의 격자로 읽히면 실패다. 육지 mask의 이웃 판정으로 해안 포말을 제한하고 색값 변화 자체를 ‘육지’로 오인하지 않게 한다.

검수용으로 128×128 art-px 영역을 여러 곳 잘라 본다. 도시가 있는 평야에서는 성곽/길/밭/수목 중 3종 이상이 식별되고, 산지에서는 능선 방향과 높낮이, 해안에서는 육지–얕은 물–깊은 물의 관계가 읽혀야 한다. 모든 영역을 똑같이 채우라는 뜻은 아니다. 넓은 바다와 들판의 휴지부는 유지하되, 노이즈로 휴지부를 채우지 않는다.

`docs/PIXEL-TIMES-STYLE-BIBLE.md`의 좌상단 광원, 지형·피부 팔레트, 1px 윤곽, 그림자 방향을 출발점으로 쓴다. 그러나 현재 파일의 남색 그라데이션 값을 유지하는 것 자체를 목표로 삼지 않는다. 기준 PNG에 맞게 UI 내부를 더 검고 중성적으로 만들고, 지도의 산림 녹색/토양 황토/깊은 바다색이 화면 주조색이 되도록 조절한다.

### 5.3 도시 등급과 특수 거점

등급은 **건물 수·성벽 구성·footprint·실루엣**으로 구별한다. 다음은 기존 atlas 크기와 호환되는 시작 규격이다. 최종값을 확정하면 style bible과 manifest를 함께 맞춘다.

| 종류 | 시작 art-px | 필수 형태 | 구현 연결 |
|---|---|---|---|
| 마을 | 24×20 또는 32×24 | 지붕 2–3개, 작은 밭/길, 성벽 없음 | village sidecar 지정 |
| 군현 | 40×32 또는 48×40 | 낮은 성벽, 작은 성문, 관청/민가 | county 자산을 원본 생성으로 교체 |
| 주요 도시 | 64×56 | 닫힌 성벽, 여러 누각, 내부 거리 | major silhouette 2종 이상 |
| 수도 | 96×80 | 궁궐·중정·성벽·탑의 복합체 | 낙양/장안 등 landmark override |
| 관문 | 40×36 이상 | 산사이 장벽·통과문·길 연결 | hulao의 `landmark` 실제 사용 |
| 항구 | 48×32 이상 | 해안 방향에 맞는 부두·창고·정박선 | land/water 앵커 분리 |

`StrategicNode.tier`의 1/2/3과 `StrategicOverlay.cityTier`의 1/2/3/4는 같은 숫자라고 가정하지 않는다. sidecar 해석 함수를 하나 두고 `capital/major/county/village/pass/port`의 명시적 종류로 변환한다. 보호된 장소 카탈로그를 바꾸지 않는다.

44px는 최소 입력 영역이다. 이미지의 최대 폭이 아니다. 도시 그림은 canvas의 정수 목적지 사각형이나 `max-width:none; flex-shrink:0`에 해당하는 별도 art layer에 놓고, DOM hitbox는 그림을 누를 수 있는 충분한 영역을 갖게 한다. 수도가 96px이면 보이는 성곽 외곽까지 클릭되는 편이 자연스럽다. 도시가 겹치는 zoom-out에서는 작게 우겨 넣기보다 작은 도시용 LOD/선택 우선순위를 쓴다.

수도와 주요 도시를 같은 PNG로 반복하기 전에 낙양·장안·성도·국내성 등 자주 보는 거점의 건축 master를 구분한다. 국내성은 중원 수도에 색만 바꾼 황금 궁전으로 처리하지 않는다. 역사적 건축의 불확실성은 기록하고, 확인되지 않은 특정 궁전 형태를 복원 사실처럼 설명하지 않는다.

### 5.4 해안·강·한반도와 카메라

타원 `land_kind()`를 지리 기준으로 계속 확장하지 않는다. 기존 `src/lib/projection.ts`, `src/lib/geo-korea.ts`, terrain 노드/연결 데이터에서 재사용할 수 있는 지리 근거를 확인하고, 부족한 해안·강 중심선은 출처가 명시된 지리 골격을 sidecar로 추가한다. 이것은 **지형 그림의 좌표 기준**이며 국경을 발명하는 작업이 아니다.

지리에서 다음 관계를 우선 확인한다: 중국 동해안과 산둥 돌출부, 발해/황해의 만과 연결, 한반도 동·서해안과 남단, 주요 강의 방향·하구, 한반도 거점과 육지/수역의 대응. 현재/고대 해안·하도 차이가 큰 부분은 정밀 복원이라고 주장하지 않고 불확실성을 명시한다. 목업의 국경이나 지도에 보이는 도시 배치를 그대로 역사 좌표로 옮기지 않는다.

현재 1000×700 overlay 좌표와 1024×704 bitmap을 하나의 transform으로 정리한다. 좌표 원본을 바꾸기 어렵다면 경계를 명시한 변환을 두어 모든 레이어가 같은 지리점에 놓이게 한다. 지도 이미지가 비균등하게 늘어나는데 라벨만 percent로 맞는 상태는 중단한다.

데스크톱 기본 카메라는 중국 주요 무대와 한반도/황해가 HUD 안전영역 안에 있도록 잡는다. 375에서는 전 대륙을 44px 타깃과 함께 한 번에 표시할 수 없으므로 다음 행동을 제공한다.

1. 기본은 현재 장의 위치를 보여 주는 지역 viewport.
2. 드래그/터치 pan과 단계식 줌으로 전체 지리를 탐색.
3. 지역 트리/사건/chronicle 선택 시 목표와 주변 지형을 안전영역으로 이동.
4. `전체 지도` 또는 `현재 장 위치` 44px 버튼으로 방향 복귀. 필요한 경우에만 작은 개요 inset을 추가.

선택 지역이 멀리 떨어졌다면 짧은 카메라 이동 또는 즉시 이동을 쓰며, 역사 시각을 연속 재생하지 않는다. `국내성`을 눌러 x=534px에 선택 표시만 남는 현재 동작은 P0 실패다. 한반도를 화면에 넣기 위해 허구의 월별 전투/항로/국경을 추가하지 않는다.

### 5.5 영토, 길, 병력, 선박

기본 지도는 삽화 지도책이다. 거점의 깃발, 실제 에피소드 관련 부대, 도시의 작은 색 포인트가 세력을 전달한다. 영토면은 필요할 때 켜는 보조 레이어로 낮추고, 기본값은 끄거나 매우 낮은 농도(시작값 alpha 0.05–0.08)로 시험한다. 자료가 모호한 경계는 확정 실선 국경으로 그리지 않는다. 에피소드와 무관한 연도 polygon을 동시에 보여 주지 않도록 sidecar의 시간 조건을 검사한다.

도로는 도시 사이의 연결 데이터 의미를 유지하되 지형을 따르는 절선/픽셀 경로로 합성한다. straight edge와 강 그림이 동시에 서로 다른 수로처럼 보이지 않도록 구분한다. 도로망을 지우는 대신 자연스러운 지도 안의 연결로 읽히게 한다.

부대 master는 infantry 군집, cavalry 군집, camp의 최소 세 실루엣으로 시작한다. 지도상 군집은 약 24–40px 안에 병사 몇 명과 작은 깃발로 읽히게 하며 named officer는 별도 상징이 필요할 때만 추가한다. 모든 도시에 동일 부대를 붙이지 않는다. episode ID/기간으로 부대 표시와 장소를 결정하고, 정확하지 않은 병력 수는 그림 수로 주장하지 않는다.

배는 최소 강선/해안선박의 두 형태를 검토하되 사용 장면에 맞는 원본을 만든다. 선체·돛/돛대·갑판·그림자/물결이 보여야 한다. 도시 이미지에 `-right-6`으로 붙이는 것 대신 수역상의 별도 앵커를 쓴다. 정박선은 부두와, 이동선은 검증된 항로와 연결한다. 한반도 교류를 강조하려고 근거 없는 해상 이동선을 추가하지 않는다.

### 5.6 Imagine과 canvas/Pillow의 역할, 정수 픽셀

**Imagine이 만들 것:** 산/숲/암벽/해안 디테일 master, 건축·항구·성문, 부대·선박의 실루엣과 내부 묘사. 참고 master를 공유하여 카메라·광원·그림자·색 밀도를 맞춘다.

**Pillow/canvas가 만들 것:** 검증된 지리 mask, 강 중심선·길·경계, seed를 고정한 지형 군집 배치, 접촉 그림자 합성, master crop/팔레트/alpha 정리, atlas 패킹, LOD, 화면 좌표·충돌. 한 장의 Imagine 세계지도 안에 도시·라벨·국경을 구워 넣지 않는다. 반대로 성곽·병사·선박의 미술을 `ImageDraw` 삼각형/사각형만으로 완성하려 하지 않는다.

정수 배율 검증은 `image-rendering:pixelated` 존재 검사로 끝내지 않는다.

- 미술 원본의 픽셀 크기를 정하고, 반복되는 지도/배우/도시 스프라이트는 1×/2×/3×의 정수 배율로 그린다. 서로 다른 해상도의 master를 무작정 같은 CSS 폭으로 맞추지 않는다.
- 확대/축소는 이산 LOD와 단계식 줌을 사용한다. viewport에 필요한 범위는 pan과 카메라로 해결한다. 실제 screen-space canvas를 쓰면 최종 blit 좌표/크기를 정수로 snap한다.
- 캔버스 backing store, CSS 크기, DPR 변환을 함께 계산한다. `Math.round(cover.w)`만으로는 원본 대비 배율이 정수가 되지 않는다.
- 원본 96×80 도시가 44×36.65625가 되는 크기, 480×270 장면의 임의 폭 확대, 비균등 종횡비는 즉시 잡는다.
- 부득이한 모바일 전체 개요는 입력을 위한 지도와 구분되는 작은 LOD로 처리한다. 정확한 정수 배율이 불가능한 경우에는 NN 샘플링과 종횡비 보존을 적용하고 그 예외를 명시한다.
- 한국어 지명·날짜·내용은 DOM이다. 지도 art를 확대할 때 텍스트까지 함께 흐리거나 작게 만들지 않는다.

## 6. Asset direction — 고유 master, 허용 변형, atlas 규칙

### 6.1 먼저 분류를 고친다

파일이 존재한다는 이유로 ‘고유 인물’ 또는 ‘고유 사건’을 완료 처리하지 않는다. 각 항목에 `characterId/eventId/placeId`, `masterId`, 원본 생성 이력, 사용 reference, 후처리 레시피, 승인 여부를 연결한다. 현재 `CHARACTER_VISUALS`에 상세 정의가 있는 인물은 9명뿐이며 PNG는 67명분이다. 나머지 58명도 이름만 붙인 변형인지, 독립 master인지 구분해야 한다.

저작권 출처는 폴더 이름으로 판단하지 않는다. `assets/eiketsu`라는 경로만 보고 불법 원본이라고 단정하지 않으며, 기존 atlas가 원본 제작인지 확인한 뒤 재사용한다. 다만 새 제작에서 KOEI 파일을 디코딩/추출/추적하는 선택지는 없다. Yokoyama 얼굴·패널·대사도 가져오지 않는다. 생성은 Grok Imagine, 후처리는 Pillow의 원본 제작 경로를 유지한다.

### 6.2 인물: 조조와 영제를 회귀 기준으로, 전체 동일 얼굴 결함을 제거

다른 **이름 있는 인물 사이의 face master 재색칠은 금지**한다. 같은 인물의 같은 시기 조명/표정 변형은 참조 master를 유지한 편집으로 만들 수 있다. 연령 변화도 눈·코·턱·수염의 정체성을 보존하면서 검수한다.

| 우선 제작 대상 | 필요한 master/수정 | 통과 조건 |
|---|---|---|
| 조인/장합, 유장/맹획 | 두 쌍의 개별 Imagine master 재제작 | 머리장식·배경을 가려도 서로 다른 얼굴·체형. master/portrait/actor/map 모두 다름 |
| 조조/영제 | 현재 구분 유지, 각각 canonical identity 확정 | 검정 관모/정치가 흉상과 황제의 관복만 다른 것이 아니라 얼굴·나이·표정도 구분 |
| 현재 첫 화면·핵심 장면 인물 | 장각, 유비, 관우, 장비, 여포, 주유, 황개, 동탁 등 실제 등장 인물 우선 | 초상·지도/장면 배우에서 같은 인물로 읽힘 |
| 한반도 이름 있는 인물 | 고국천왕·을파소 등 실제 연결되는 항목부터 개별 master | 사마의/제갈량 재색칠 금지, 복식 근거와 불확실성 기록 |
| 나머지 이름 있는 인물 | 순서대로 독립 master와 identity sheet | ‘67/67 파일 있음’ 대신 시각 검수 완료 수로 집계 |

초상은 원본 64×80 흉상 규격을 유지할 수 있다. 최종 얼굴의 눈·코·턱·수염·주름이 충분히 남도록 **인물별 crop box**를 정한다. 모든 전신의 윗부분 58%를 같은 방식으로 늘려 채우는 것은 모자 크기/무기 위치에 따라 얼굴 크기를 바꾼다. 첫 프레임부터 몸·머리 비율을 기준 초상과 대조한다.

의상/갑옷/장식에만 세력색 마스크를 적용한다. 피부·머리카락·배경까지 RGB 채널을 교환하지 않는다. 청록/마젠타 잔류를 제거하고, portrait는 공통의 어두운 배경+얇은 테두리로 합성한다. 반투명 키 잔류나 정사각 색 배경은 atlas 승인 실패다.

검수는 이름을 숨긴 64×80, 2× 확대, 머리장식/색을 가린 얼굴 crop의 세 보기로 한다. 픽셀 hash는 완전 복제 탐지용, perceptual 비교와 얼굴 crop 검토는 유사 얼굴 탐지용이다. hash가 다르다는 이유만으로 고유성을 승인하지 않는다.

### 6.3 지도/장면 배우

portrait/master와 같은 신체·얼굴·수염·모자·무기를 가진 전신을 Imagine에서 참조 제작한다. 지도 officer 32×64와 scene actor 48×64는 출력 계약으로 유지할 수 있지만, 작은 해상도에서 필요한 실루엣을 다시 정리한다. 큰 전신을 단순 축소해서 노이즈가 된 무기/팔/수염을 그대로 두지 않는다.

2프레임 idle은 발 접점을 고정하고 옷자락·호흡·무기 또는 깃발 한두 픽셀을 움직인다. 인물 전체가 위아래로 떠다니는 f1을 기본 품질로 삼지 않는다. 걷기가 필요할 때만 방향/걷기 프레임을 추가하고, 생성된 `imagine-raw/*idle-f1.png`가 실제 최종 atlas 셀에 반영되는지 확인한다. 서로 다른 포즈가 아니라 작은 움직임이어야 한다.

익명 병사는 동일 원본의 군복/방패/깃발 부분 palette swap을 허용한다. 이름 있는 무장의 얼굴과 실루엣을 다른 무장에게 재할당하지 않는다. 단일 인물을 unit blob으로 반복 복사하는 대신 병사 군집용 master를 별도로 둔다.

### 6.4 사건 배너와 장면 배경

현재 세 배경을 72개 이름으로 늘린 파이프라인을 생산 승인 경로에서 제외한다. 다음 master를 우선 확정한다.

| 사건/용도 | 반드시 읽혀야 하는 그림 | 재사용 가능 범위 |
|---|---|---|
| 황건 봉기 `v01-e01` | 누런 수건·깃발, 집결한 사람/부대, 군현의 긴장 | 같은 봉기 계열의 다른 화면 crop, 실제 장소 표현 검수 필요 |
| 도원결의 `v01-e04` | 복숭아밭, 세 사람의 맹세를 위한 자리 | 같은 장면의 banner crop/확대 background |
| 호로관 `v05-e03` | 산사이 관문, 진영, 대치/일기토 공간 | 같은 관문·전투의 상세 crop |
| 낙양 화재 `v06-e01` | 도성/궁성의 화재와 도시의 실루엣 | 같은 도성 사건의 crop. 배가 타는 적벽 원본 사용 금지 |
| 관도·오소 `v16-e03` | 군량고/수레/야영지와 국지 화재 | 군량 탈취/화재의 승인된 관련 장면 |
| 적벽 `v26-e01` | 큰 강과 연속된 선박·화공 | 수전 안에서만. 육상 화재 대체재 아님 |
| 융중대 `v21-e02` | 초옥/대화 공간, 초청과 논의의 분위기 | 같은 초옥 장소. 복숭아밭으로 대체 금지 |
| 한반도 동시대 상태 | 해당 거점/궁정/마을의 평온한 맥락, 필요하면 지도 vignette | 근거 있는 동일 지역 환경. 교전 기록이 없으면 군사행동을 그리지 않음 |

banner 320×180과 scene background 480×270는 같은 사건의 세계를 공유하되, 작은 banner를 확대해서 배경으로 쓰지 않는다. 더 큰 원본에서 각각 crop하거나 같은 reference로 확대 무대를 제작한다. banner에는 사건을 알아볼 주된 실루엣/행동이 남고, scene background에는 배우 발이 닿을 바닥과 전경/중경/후경이 남아야 한다.

날짜·제목·설명·테두리는 `EventBanner`의 DOM 책임으로 돌린다. PNG에 한국어/날짜 띠를 구워 넣은 뒤 또 DOM 텍스트를 덧붙이지 않는다. 현재 `build_event_banners.py`의 기본 폰트 한글도 읽기 어려운 점/칸으로 남을 수 있으므로 이미지에는 그림만 남긴다.

보조 사건에 매번 별도 대형 원화를 요구하지는 않는다. **사건 분류와 장소가 맞는 승인된 원본**을 crop/구도 변경할 수 있다. 대신 의미가 다른 사건을 hash modulo로 배정하는 방식은 전면 중단한다. 주요 사건은 독립 master, 보조 사건은 근거 있는 family reuse라는 구분을 manifest에 남긴다. 확대 scene이 없는 배너에는 가능한 상세 경로를 제공하고 클릭해도 아무 변화 없는 동작을 남기지 않는다.

### 6.5 도시 compound·지형·함선 master

수도/major/county/village/pass/port를 하나의 reference family로 Imagine에서 제작한다. 수도·군현 사이에 현재처럼 섬세한 디오라마와 `ImageDraw` 사각 집이 섞이지 않아야 한다. 여러 구조를 조합하는 수도 compound는 성벽/궁궐/탑/민가의 원본을 따로 만들고 Pillow로 조립해도 된다. 이 경우에도 앵커·카메라·벽 두 면·광원은 같아야 한다.

팔레트/방향/crop 변형이 허용되는 것은 같은 건축 family의 작은 지붕, 익명 마을, 지형 수관, 같은 선종의 돛/깃발이다. 수도 종류를 만들기 위해 작은 집을 4배 확대하거나 육상 부대를 배 아이콘으로 변형하지 않는다. 광원이 좌상단이면 수평 mirror도 그림자/조명을 함께 보정하지 않는 한 함부로 쓰지 않는다.

생성 prompt 공통 머리말에는 원본 pixel art, ¾ quarter-view, 좌상단 광원, 선택된 팔레트, 경계/그림자 규칙, 최종 축소 후 읽힐 실루엣, 무문자·무워터마크·무 UI를 넣는다. 자산별 차이는 건축 규모/무기/얼굴/행동/장소로 명시한다. provider 호출·모델 선택은 프로젝트의 Grok Imagine 경로를 따른다.

### 6.6 Atlas와 승인 절차

기존 `portrait-atlas.png/.index.json`, `scene-actors.png/.index.json`, `map-characters.png/.index.json`의 역할을 유지한다. 현재 실제 cell 수는 67 / 134 / 67이다. `PT_MANIFEST`의 actor/map atlas 높이는 실제 파일/rowCount와 함께 대조해야 한다. 선언된 2176/1088 같은 수치가 실제 34×64/17×64를 뜻하는지 확인하고 임의로 새 슬롯을 추가하지 않는다.

1. master/최종 crop/alpha/팔레트를 개별 검수하고, 승인 목록으로만 pack한다.
2. 셀 순서와 ID 매핑을 결정적으로 고정한다. 기존 ID는 유지하고 새 데이터는 sidecar로 연결한다.
3. 최종 PNG와 index의 cellW/H·cols·rows·좌표·bounds를 검증한다. 고정 셀 방식에 임의 gutter를 추가해 좌표를 어긋나게 하지 않는다. 필요하면 packer/loader/index를 함께 변경한다.
4. atlas 셀 crop이 독립 portrait/actor/map 파일과 픽셀 단위로 일치하는지 확인한다. 파일을 교체했는데 runtime atlas가 옛 그림인 상태를 잡는다.
5. 투명 배경/잔류 키색/잘린 무기/잘린 발/프레임 anchor를 확인한다. 피부색은 전체적인 자연 팔레트 범위에서 본다.
6. 성명별 완전 중복·유사 얼굴·잘못된 이름 매핑을 검수한다. 조조/영제, 조인/장합, 유장/맹획은 고정 회귀 쌍이다.
7. 최종 runtime에서 `KaoPortrait`와 actor가 어느 sheet를 실제로 참조하는지 확인한다. provenance 미확인 구형 JPG/atlas로 조용히 fallback하면 정체성 검수는 실패다.

일괄 스크립트를 재실행하면 승인 자산이 되돌아갈 수 있다. 특히 `build_world_map.py`는 지도뿐 아니라 `match_banners()`와 단순 `landmarks()`도 다시 저장한다. 구현자는 생성 책임을 분리하거나 승인된 출력의 overwrite 정책을 명시한 뒤 실행해야 한다. 방향 문서 작성 과정에서는 이 스크립트들을 실행하지 않았다.

## 7. Next visual QA gate — 네 폭과 두 기준의 비교

### 7.1 다음 게이트의 캡처 상태

기준 PNG 두 장을 QA 화면 옆에 항상 연다. 제품 목업은 전체 구도, 스타일 가이드는 지형/도시/초상/배너의 가까운 비교에 쓴다. 이번에 본 과거 `docs/qa/` PNG를 최신 실행 결과로 대체하지 않는다.

각 375×812 / 768×1024 / 1440×900 / 1920×1080에서 동일 episode와 동일 카메라 초기 조건으로 다음을 캡처한다. 다음 구현자는 그때의 스크린샷을 durable evidence로 저장한다.

1. `/world?episode=v01-e01`: 초기 지도. 네비/chronicle 기본 접힘 상태.
2. 책 트리 하나 열림: 권/장 관계와 지도 가시성.
3. 지역 → 한반도 → 국내성 선택: 실제 선택점과 주변 지형이 화면 안에 들어오는지.
4. 대표 사건 선택: banner·도시·라벨·HUD의 충돌.
5. `v01-e04`, `v05-e03`, `v26-e01`: 배너와 scene의 소재 일치, 배우/초상/출처/다음 대사/닫기.
6. `v06-e01`, `v16-e03`: 도성 화재/군량고 화재가 배 화재 그림으로 남지 않았는지.

전체 화면을 가로 320px 정도의 thumbnail로 줄여 먼저 본다. 이때 글자를 읽으려 하지 말고 무엇이 화면을 지배하는지 본다. 다음에 100% 화면으로 읽기·타깃·충돌을, 마지막에 원본 픽셀 확대를 확인한다. 미술 검수용 비교에서는 smoothing이 섞이지 않게 하고, 지배적인 덩어리 비교용 thumbnail은 동일 축소 방식을 양쪽에 적용한다.

| 카메라·한국 | 지역 선택 후 국내성과 주변 지리/경로가 안전영역 안에 있음 | selected=true지만 화면 밖, pan 불가, 지도 가장자리 잘림을 overflow 0으로 합격 처리 |
| 도시 등급 | 이름을 가려도 마을/군현/도시/수도를 크기와 구조로 구분 | 모두 44px, 작은 집이 수도보다 커 보임, 같은 긴 성곽 도장이 반복 |
| 지형 | 산맥 방향·수관·하구·해안선이 이어지고 지역별 밀도가 다름 | 평야 전면 노이즈, 삼각 산 줄무늬, 직각 해안, 물 전체 포말 |
| 배/군대 | 돛단배와 군집 병사가 1×에서도 식별 | 빨간 막대/검은 삼각형으로만 보임 |
| 배너 | 그림에서 사건 종류가 구별, 날짜/제목 DOM, 지도 앵커 연결 | 황건=빈 산문, 적벽=복숭아밭, 낙양=불타는 배, 이중 텍스트 띠 |
| 충돌 | HUD/배너/선택 도시/우선 라벨이 서로 가리지 않음 | 카드만 안 겹치고 그 아래 클릭점이나 지명이 사라짐 |
| 초상 정체성 | 이름·세력색·모자를 가려도 주요 인물을 구분 | 다른 이름 같은 얼굴, 녹색 피부, 청록/자홍 사각 배경, 복제 hash |
| 장면 | 배우가 장소 안에 서고 얼굴/무기가 초상과 이어짐. 지도 복귀 보존 | 하단 정렬된 배우 줄, 배경이 화면 전체로 임의 확대, 닫은 뒤 위치 초기화 |
| 입력 | 보이는 대상을 누를 수 있고 44×44px 이상 타깃이 겹치지 않음 | 클릭 영역만 커져 다른 버튼을 덮음, 큰 도시의 외곽은 클릭 불가 |
| 이산 시계 | 이전/다음 장·다음 권에서만 전역 상태가 바뀜 | 자동 진행, 배속, scrubber, scene idle 때문에 역사 시각 진행 |

pixel scale 검수는 DPR 1에서 실제 `getBoundingClientRect()`와 canvas backing size를 기록한다. 가능하면 DPR 2에서도 한 번 확인한다. no-horizontal-overflow, 콘솔 오류 없음, 로딩/프레임워크 overlay 없음도 확인하되 이것을 시각 점수로 대신하지 않는다.

### 7.3 점수와 재작업 규칙

`Prompt.md` §15의 가중치를 그대로 사용한다.

|---|---:|

| Pixel-art consistency | 20 |
| UI chrome consistency | 15 |
| Information hierarchy | 10 |
| Character consistency | 10 |
| Event banner quality | 10 |
| Historical atmosphere | 5 |
| Mobile readability | 5 |
| 합계 | 100 |

다음 주요 시각 마일스톤은 **90/100 이상**을 목표로 하고, 미달하면 가장 낮은 축을 고쳐 재촬영한다. 이번 방향 검토에서 근거 없는 현재 점수를 꾸며 적지는 않는다. 다음 점수에는 각 항목의 실제 screenshot와 남은 감점을 붙인다. Grok 4.6 이미지 이해로 두 reference 대비 검수하되 수치만 제출하지 말고 눈으로 확인한 불일치도 기록한다.

90점이어도 다음은 별도 차단 조건이다: 이름 있는 인물 완전 복제, 잘못된 사건 소재, 접근 불가 한반도, 근거 없는 한국 전투/국경, 보호 카탈로그 변경, KOEI/Yokoyama 복제, 전역 autoplay, 375px 가로 overflow, 주요 입력 불능. 이 조건을 점수 평균으로 상쇄하지 않는다.

구현 통합 후에는 `npm run build`, `npm run lint`, `npm run verify`와 영향받는 실제 경로의 Playwright 검증을 실행한다. 기존 검증을 낮춰 합격시키지 않는다. 이 방향 문서만 작성한 이번 작업에서는 앱 build/lint/verify를 새로 실행하지 않았다.

## 8. Stop doing — 목표를 거스르는 습관과 실행 순서

- ‘지도 전체 화면화’를 다시 구현하거나 과거의 세로 페이지 진단을 그대로 반복하지 않는다. 남은 것은 지리 접근과 화면 안의 미술이다.
- 남색 창을 줄인다는 이유로 모든 글자를 작게 만들지 않는다. 중복 날짜·설정·창 테두리의 역할을 줄인다.
- 목표의 풍부함을 UI 패널 개수나 상시 노출 카드 개수로 흉내 내지 않는다. 지도 자체의 사물 밀도를 먼저 올린다.
- 같은 삼각형·수관·흰 점을 더 찍어 ‘고밀도’라고 부르지 않는다. 저주파 형태와 군집이 먼저다.
- 국가/해안/강을 타원·색 영역으로 대략 만들고 실제 지명이 있으니 지리성이 충분하다고 판단하지 않는다.
- 44px 접근성 규격을 모든 스프라이트의 최대 크기로 사용하지 않는다. 픽셀 배율은 클래스 이름이 아니라 실제 크기로 검사한다.

- 다른 이름의 초상을 재색칠하지 않는다. 조조/영제 쌍이 현재 구분된다고 해서 전체 같은 얼굴 결함이 해결됐다고 주장하지 않는다.

- 배너의 map-% clamp, 낙양만의 예외, 무조건 최대 두 카드로 충돌을 해결했다고 처리하지 않는다. 실제 viewport와 HUD를 예약한다.

- 테스트 통과, 콘솔 깨끗함, PNG 개수, 스타일 바이블 존재를 시각 품질의 대리 지표로 쓰지 않는다.
